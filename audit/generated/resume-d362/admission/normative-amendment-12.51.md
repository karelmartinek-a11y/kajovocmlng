### 12.51 Immutable podklady admission jednotlivých generation kinds

Tato technická specializace §12.41 a §25.11 rozlišuje založení discussion jobu od execution authority, provádění plánu a activation. Každý úspěšně založený job zůstává v `DISCUSSING` podle vlastní initial state v §49.15. Admission ani model proposal samy nevytvářejí approval, release, runtime, binding, produkční side effect nebo úspěšný execution receipt.

Přesná versionovaná maska `contracts/generation/admission-basis.schema.json` a request projekce `contracts/create-operation-design.schema.json#/$defs/GenerationJobCreateBody` společně určují `generationBasis`. Neznámé pole, null, jiné datové typy, nerozpoznaná varianta a chybějící povinná pole se odmítají. Varianta se nikdy nehádá z formátu. HTTP path/query/header a strict UTF-8 JSON pravidla §12.47 zůstávají účinná; operace nepřijímá query parametry. Identita nového jobu, serverová authority, schema/content digests, receipt a guarda nejsou klientem vytvořená důvěryhodná pole.

| kind | `basisKind` | povinná pole `generationBasis` | vlastní podklad a admission |
|---|---|---|---|
| UPDATE | `UPDATE_TARGET_REVISION` | `snapshotId`, `expectedDigest` | Owned immutable target snapshot skutečných bytes s přesným object/kind/revision/release/component/runtime identity bindingem. `targetKind` a `targetObjectId` jsou povinné. Discussion smí začít před dokončením compatibility a migration planu; ty jsou povinné před execution. UPDATE nesmí změnit component/runtime identity. |
| RETRY | `RETRY_FAILED_TECHNICAL_PART` | `phaseRunId`, `expectedDigest`, `planId`, `expectedPlanDigest`, `approvedRevisionId`, `expectedSpecificationDigest`, `authorityId`, `expectedAuthorityDigest` | `parentJobId` je povinný. Přesná immutable approved specification a authority se vážou na autentický commit OWNER approval; přesný source phase attempt je terminal `FAILED`, actual result dokládá známé selhání a žádný pending UNKNOWN side effect. Failed node IDs jsou právě z jeho native source planu a stejné fáze; discussion turn není technická retry část. Parent job nemusí být plošně terminal. Nový execution použije stejnou approved functional authority, pouze neúspěšnou technickou část a nové attempt records podle vlastní sequence §49.15. |
| REPAIR | `REPAIR_MONITORING_EVIDENCE` | `monitoringArtifactId`, `expectedDigest`, `snapshotId`, `expectedTargetDigest`, `approvedRevisionId`, `expectedSpecificationDigest`, `authorityId`, `expectedAuthorityDigest` | `targetKind` a `targetObjectId` jsou povinné. Current locked target head se váže na přesný immutable snapshot jeho last-approved authority/revision/digest, nikoli libovolnou starou approved revision. Podklad je skutečný committed `MONITORING_EVIDENCE` artefakt s ověřenou publication receipt, native EvidenceRecord, target subject digest a actual observation bytes proti exact frozen observation schema. Zachovává identity a poslední approved functional lineage; smí měnit pouze technickou implementaci. Úplná regresní validace je povinná před activation. |

Všechna selector identity pole jsou UUID; všechna `expected*Digest` pole jsou `sha256:` a přesně 64 lowercase hex znaků. Každé pole uvedené v tabulce a `basisKind` je required a non-null. Jde o nedůvěryhodné client selector hints a digest preconditions; jejich existence neprokazuje oprávnění, approval, validitu nebo dostupnost bytes. Exact field source/meaning/schema/origin je materializován ve `contracts/generation/admission-basis.json#/fields`: spelling a diskriminace jsou technické doplnění §12.18, immutable revision/source authority §25.11, own kind semantics §12.41, phase terminality §49.15 a server digest/identity §49.4.

`generationBasis` je nepřípustná na CREATE a FOLLOW_UP. FOLLOW_UP používá již schválenou `followUpBasis` masku §12.49 a může vycházet z nonterminal source jobu. Jeho source bytes musí být skutečně dekódované: INITIAL_REQUEST jako exact native GenerationJobCreateBody; SPECIFICATION_REVISION jako native GenerationSpecification patřící source jobu; PUBLISHED_FINAL_OUTPUT jako native artefakt podle frozen artifact-kind/schema mapy s přesnou retained publication receipt. Plain text fixture, JSON schovaný ve stringu nebo samotný příznak `consistent`/`sufficient` nejsou obsahový důkaz. Explicitní workflow input contracts určují, který podklad je pro konkrétní downstream použití dostatečný; dostupnost frozen lineage nenahrazuje dosud nepublikovaný požadovaný finální výstup.

Hydratace každého podkladu ověří server-owned immutable primary key, owner a job binding, skutečné bytes, přepočtený content digest, selector precondition, exact `SchemaAddress` a skutečné bytes celého frozen schema bundle. Native JSON se validuje kompletním registry a canonical UTF-8 serialization; duplicate keys, neplatné UTF-8/JSON/Unicode a nonfinite numbers se odmítají. Chybějící povinné schema nebo unresolved reference nejsou PASS. Native `GenerationSpecification.authorityModel` se musí hydratovat jako exact `GENERATION_AUTHORITY` record a jeho skutečné native GenerationAuthority bytes odpovídat zachovávanému authority snapshotu. Source document `jobId` i authority `sourceJobId` se ověřují proti persisted record jobu, i když REPAIR nepředává parent job jako request pole.

Historický authority target snapshot se při existenci ověřuje pro zachování object/component/runtime identities. Jeho historical revision, binding counter a activation epoch se nepovažují za dnešní current snapshot; plná digest equality těchto různých časových snapshotů se nevynucuje. REPAIR naopak atomicky ověří today's current target head a jeho last-approved lineage. Čtení moving pointeru bez frozen snapshot identity je nepřípustné.

Frozen lineage obsahuje všechny skutečně použité immutable record identities/content digests/schema addresses a digests všech použitých schema bundles: source specification, native authorityModel record, source authority snapshot, OWNER approval receipt, phase failure result/plan, target snapshots, monitoring evidence, observation schema a publication receipts. Digest se počítá z tohoto uzavřeného consultovaného dependency setu. Pozdější source job progress/failure/cancel ani current pointer nepřepisují frozen inputs. Replay stejného locator/digest použije původní persisted frozen execution descriptor a nepřijímá nový current kontext ani nový event.

Authenticated OWNER, exact identity/eligibility a current target/phase/recovery heads se ověří atomicky pod locks v témže create commit podle §49.4/§51.12. Root/request/basis, kanonický outcome, typed event, transactional outbox a audit se commitují společně. Technical authority inheritance, current dependency/fence/reconciliation a full native graph/consumer postconditions se znovu ověřují před execution; source approval není oprávnění měnit behavioral requirements, external semantics, exact bindings nebo OWNER decisions (§12.22).

Finite diagnostický registr `contracts/generation/admission-diagnostics.json` určuje přesný predicate, source, pointer a mapování na účinný `CREATE_INPUT_INVALID`, `CREATE_REFERENCE_INVALID` nebo `CREATE_POLICY_UNRESOLVED`. Invalid persisted source JSON je reference error, nikoli důkaz chyby caller HTTP. Mandatory missing schema/bytes/approval/evidence kontrakt blokuje policy. Unknown diagnostic zůstává `HTTP_FAILURE_PROJECTION_UNRESOLVED`; nepovoluje se prefix catchall. Odpovědi, eventy, logy a důkazy neobsahují source sensitive bytes.

Tato maska sama neuzavírá celý §12.20 source ContractRecordRef graph, jeho predicate implementation bytes nebo target monitoring profile → repair-policy predicate. Discussion candidate content validation není důkazem povolené automatické technical repair dispatch; přesný monitoring consumer predicate je mandatory before execution. PostgreSQL fixture role/FK/locking/commit/replay důkazy jsou povinná předgenerační práce. Future application runtime acceptance zůstává oddělená a NOT_EVALUATED, dokud není skutečná implementace ověřena.
