## Explicit transition: no hidden interpretation of current value

The draft adds a closed `value` branch:

`{ "representation": "PROFILE_JSON_V1", "profileId": "<one exact registered name>", "profile": { "variant": "<same exact registered name>", ...exact fields... } }`.

Each profile has a closed own schema, own discriminator and a `type` dependency. A profile's string fields are ordinary values, not JSON hidden in a string. Unknown representation, unknown profile, extra fields, null at nonnullable fields and incompatible type/profile are rejected. The current `{encoding:UTF8,text:...}` / `{encoding:BASE64,base64:...}` remain explicit RAW shapes. No text parsing, PEM sniffing, JWT inspection or automatic RAW→PROFILE promotion is allowed. Six opaque types continue using their existing RAW interpretation; nine complex types require PROFILE on new creates because their prior raw content policy is currently unverified, not because legacy persisted values are magically migrated. Existing legacy versions retain their own RAW discriminator and bytes. Migration, if needed, is an authorized new immutable version with an explicit selected profile; it never rewrites an old version.

No query/path additions are proposed. Existing POST `/secrets`, authorization, idempotency header and strict HTTP decoding remain. A required import `profile` is validated using the actual incoming raw JSON object span, so original escapes, whitespace and sensitive strings survive without reserialization. Request canonical digest computation may have its own existing algorithm; it never becomes a substitute for stored original bytes.

## Load → consumer relation

`load_reference` now requires the external requested `secretId` and `versionId`, rejects substitution of another genuinely authenticated ciphertext, checks authenticated metadata, exact schema/type/representation and raw plaintext digest/length, then revalidates the pinned parser. Matching internally stored metadata against itself is insufficient. The production caller's exact requested tuple comes from the broker's retained resolution, not a model or arbitrary client.

`ConsumerDeclaration` is closed: consumer identity/revision/purpose, compatible `(type,profileId,schemaDigest)` pairs, target origins/hosts, endpoint/database binding, exact key algorithm policies, TOTP parameter policies, browser members/serializers and engine build. This is a server-authored pinned contract, not import authority. Unsupported variant or schema fails specifically without fallback. Full OAuth endpoint equality (including path/query) and client ID/scope binding are tested; comparing only hostname is insufficient. DB connection endpoint/vendor/TLS stay in target binding; optional duplicate database in imported value must match it at use. Outer UI `url`/`username` remain display metadata; credential `profile.username` and target binding are the only authentication sources. They must not become competing trusted values.

Candidate import and use eligibility differ: an expired token or untrusted/self-signed certificate can be imported as a candidate when syntactically valid; use must pass consumer expiry/trust/target policy and actual binding. Consumer key algorithms include explicit RSA modulus/exponents, EC curves, DSA sizes or named Edwards algorithms; parser support is never global permission. TOTP seed security and clock/period policy belong to the exact consumer, not an invented universal ten-byte/300-second import rule. Reference preflight is not real authentication. An arbitrary `valid=true` or cookie presence is never an account receipt.

## Full browser member profile and technical serializers

The additional profile explicitly models: partitioned/unpartitioned cookies with host-only flag, SameSite/secure/httpOnly and exact binary64 fractional expiry; per-origin localStorage; per-page/origin sessionStorage; IndexedDB database/store/index/key-generator/record schema; per-origin permission state; exact client-certificate Secret-pair or OWNER Device Bridge metadata; and virtual automation-account WebAuthn credentials. Real platform passkeys/private keys are forbidden by the profile, as required by §13.15.

IndexedDB keys are tagged STRING/NUMBER/DATE/BINARY/ARRAY; values use `ECMASCRIPT_AUTH_CLONE_GRAPH_V1`, a closed tagged graph for primitive values, bigint, dates, object/array/map/set, ArrayBuffer/typed views, RegExp, Blob/File. Explicit graph IDs preserve cycles/shared references. Dangling and duplicate IDs, invalid buffer ranges, illegal `u+v` flags, duplicate Map keys and Set values by actual SameValueZero (including NaN and signed zero) reject. No arbitrary object, unversioned binary engine dump or ignored extra member is accepted. Unsupported structured-clone objects require an explicit tested member profile if a required adapter actually uses them; this profile is not permission to drop a required member.

Numeric IndexedDB key versions/generators use ECMAScript exact integer boundaries (the exhaustion sentinel is explicit); signCount uses its WebAuthn uint32 representation. Base64 and IEEE754 byte encodings are strict and preserve exact input. Unjustified 4096-character/item caps, 32-certificate chains, ten-byte seed and 300-second TOTP caps were removed. The existing whole HTTP body byte bound is documented separately. Engine limits are declarations of the exact installed consumer, not assertions that the SSOT globally forbids another valid value.

Capture uses mutation barrier, no pending unknown side effect, authenticated account/tenant marker and exact member inventory. Captured server bundle identity/epochs/digests are outside the client candidate profile and are created by server authority. Restore creates a fresh context, installs cookies/storage before navigation and sessionStorage before bootstrap, validates every requested member/capability and then proves actual account/tenant/epoch postconditions. Missing serializer, bridge resolution, partition capability or WebAuthn support rejects; no partial-authenticated success. Activation pointer CAS checks account binding/auth epoch/credential version and must not resurrect a concurrent logout/rotation.

**Browser integration is still OPEN:** reference schema/graph tests do not prove actual engine capture/restore, IDB keyPath/index uniqueness and key-generator reconstruction, client-certificate binding resolution, WebAuthn assertion signatures/attestation, or provider account postconditions. These explicit technical obligations may require pre-generation isolated fixtures; real external authentication remains future implementation acceptance. The draft must not be presented as universally VERIFIED or overwrite the complete §13.15 contract with the limited cookie/localStorage profile.
