# Late-H receipt origin replaces the rejected pre-C context ticket

Root's ordering review invalidated the original publisher interface for whole-order readiness: a persisted H authentication/context row is needed to create its nominally pre-C ticket. Original candidate and proofs remain historical, and its producer ID stays IN_PROGRESS.

This replacement has no B/credential/session/owner/release query or lock in the ticket function. An automatic AFTER INSERT trigger on the exact canonical authentication-acceptance table emits a private immutable origin row carrying the database current transaction ID. The trigger function rejects any other table/schema/operation, has no PUBLIC execution grant and cannot be ordinarily called as a SQL function. The domain writer cannot fabricate origin rows. A late-H ticket requires the exact newly inserted receipt/context and current origin; old contexts/receipts cannot authorize a new transaction ticket. The actual native verifier remains the producer: private single-use actual-token material holds A/B while C claims and E roots are acquired, and the receipt/context are persisted late H. No boolean or caller preheld lock declaration substitutes for that producer.

`verify_late_origin.py` initially ran 7 real PostgreSQL18.6 assertions against actual bearer-verifier receipts: automatic origin, current ticket, forbidden direct origin fabrication, trigger-only invocation, immutable origin, old-receipt new-transaction denial, no lower-lock statements. The test setup uses the known legacy H-before-C constructor, so its scope is explicitly only receipt-origin/ticket mechanics. The stricter trigger-source guard was added and the actual 7 assertions were reexecuted successfully; the report records its exact consumed SQL hash.

Required connected proof: native author's ordered constructor must remove explicit late A/B FOR SHARE statements; its ordered factory must call the late ticket after genuine H receipt/context persistence and before package publication. Verify actual authenticated B → C0/C1 → E roots/source → H receipt/origin/context/ticket/package → event/outbox → I audit COMMIT, rotation race, rollback and prior-context/malformed material negatives. Exact H child namespaces for auth origin and ticket need coordinator integration; these table FK writes cannot be omitted from global ordering review. Existing archive publication/binding functions also have immutable FOR SHARE/FK locks; their ordered positions require review independently of this ticket change.
