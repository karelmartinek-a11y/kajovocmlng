# Coordinator-owned normative amendment proposal — exact read/RAW retention

Authorities: §§7.2,8.5,8.12,25.6,49.22.1,51.6–8,51.20. No new product profile or permission is introduced. The following is a technical materialization proposal, not an already effective clause.

The non-reserved `secret.value.read` OWNER_API path verifies the exact current bearer token using the canonical constant-time API verifier while holding platform/deployment heads and current credential B3 SHARE. Its finite lock plan then locks OWNER_IDENTITY ordinal10 and all known credential/value SECRET_RECORD ordinal20 roots in UUID order. The server must not reuse `secret.create` context or interpret a caller owner UUID as read authority. Authentication precedes disclosure of target/version diagnostics and plaintext opening. The current immutable value is selected from the locked root; an internal explicit immutable selector must belong to the same Secret. The existing GET /secrets/{id}/value accepts no body and either no query (native selector kind CURRENT) or exactly one versionId canonical UUID query (native selector kind IMMUTABLE_VERSION). Reject unknown/duplicate queries and wrong UUID encodings. Exact closed mask secret-value-read.schema.json is authored with UI registry page13 actions1/2 active/selected reveal and same displayed-value copy; no other permission is granted. The server consumes record_status_v1 and denies DELETED even for a historical selector. Status integrity failures are not silently INACTIVE; authenticate before exposing their precise diagnostics.

Canonical immutable nonce/key authority and original creator context/logical operation bind the exact encrypted version fields, representation, type, schema IDs/digests, lengths and exact original/canonical value digests. Actual canonical authenticated opening and native original-representation validation precede success evidence. OWNER value visibility is distinct from runtime variant/target eligibility: historical RAW is returned in its original representation without format inference, reinterpretation or profile activation. Expired/not-target-eligible import candidates are not thereby forbidden from OWNER inspection. Reserved `KCML_OWNER_API_KEY` reveal retains its own OWNER-session authority; a valid API token alone does not authorize that reveal.

The retained OWNER read evidence is committed before response publication. The bounded `owner_value_read_audit` projection must be joined to the effective canonical global audit/access event producer; its append-only rows alone are not the complete audit chain. Deny/timeout/crash evidence has its own retained decision producer and cannot be fabricated by an unrelated exception.

The storage contract must allow authentic historical immutable RAW versions required by §8.12 without reopening fresh complex RAW import. `legacy_raw_origin` is a restricted restore/archive publication boundary, never a client `legacy=true` field. It retains exact original schema bytes/digest/source identity and exact retained admission receipt, encrypted immutable row bytes/digest and original creator/logical operation identity. Its deferred invariant verifies the same Secret/version, exact encrypted immutable fields and matching canonical nonce metadata. Fresh native create policy remains unchanged and rejects complex RAW as `SECRET_PROFILE_REQUIRED`. The original semantic admission/schema/archive producer must authenticate these records; structural SQL/ACL/digest checks alone cannot certify historical authorization. Do not activate a migration that merely admits a self-reported old receipt.

The broad runtime broker candidate remains separate: resolving the actual current binding/source-target revisions/activation/barrier/consumer purpose/placement and one logical-operation version pin cannot use fake source-head roots. Exact original source/target root-kind FKs and §51.6 lock plan, actual runtime gateway execution context/pending capability producer, full audit and invalidation producer are required before its canonical activation. Canonical nonce/key registry uniqueness and synthetic AES fixture keys are not actual systemd credential provisioning proof.

The exact current credential Secret root must itself project ACTIVE under its held root lock. A DELETED reserved root with a still-ACTIVE historical pointer cannot authorize any API read; the actual PostgreSQL fixture rejects this state as OWNER_VALUE_READ_AUTHORITY_BINDING_INVALID. This consumes the shared approved status producer, not an independently invented lifecycle.
