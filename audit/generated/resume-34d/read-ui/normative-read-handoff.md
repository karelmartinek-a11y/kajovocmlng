### Generation create: závazná read/hydration předávka

Toto ustanovení materializuje §12.48, §12.49, §25.11, §49.3–5, §51.2 a §51.10. Nemění význam `generation.job.read` ani `generation.job.snapshot.read`; úzká create-consumer projekce nenahrazuje celý jejich povinný nativní výstup.

1. Read přijímá pouze přesný path `id` podle route.0217/0218; query, body a klientská execution authority nejsou alternativním zdrojem identity. OWNER identity pochází z aktuálně autentizovaného serverového read kontextu. Uložení původního create contextu nedává oprávnění novému čtenáři. Owner UUID předané repository funkcí není samo autentizací.
2. Jedna repository statement snapshot nebo deklarovaná `REPEATABLE READ` transakce načte current `generation_job` a přesné frozen CREATE rows. SELECT nesmí nahradit vybraný job globálním latest pointerem, odvodit parent identity z názvu ani načíst každou část v jiné current verzi. Čtení nevytváří další command/event/outbox/audit řádek.
3. Internal storage read má všech 39 fyzických root polí podle přiložené přesné masky a field mappingu. UUID zachovává identitu, bigint se převádí na kanonický nezáporný decimal string s nejvýše signed bigint hodnotou, digest je `sha256:` + lowercase hex, timestamp RFC3339. SQL NULL zůstává JSON null. `currentPhase` a `errorCode` vyžadují svůj vlastní účinný slovník; syntaktický string není jeho náhradou.
4. Frozen creation command se najde přes `generation_job_initial_request_snapshot.logical_operation_id`, nikoli přes mutable `latest_command_logical_operation_id`. Typed generation binding musí spojit přesný context a snapshot. Root/snapshot/completion/event/outbox/audit/locator/idempotency jsou propojeny stejnou job, operation, digest a sequence identitou. Následný current job stav a counters mohou legitimně postoupit; frozen `generation.job.created` receipt/event se nepřepisují.
5. Public create-consumer projekce obsahuje pouze vlastní current state/version/sequence a potřebné identity. Celý internal root, lease/fence/context descriptor, ciphertext/nonce/key material a dešifrovaný request nejsou public read výstupem. Samostatný OWNER reveal Secrets zůstává pod vlastním explicitním kontraktem.
6. Chráněný request se otevře pouze v serverové repository hranici pomocí canonical crypto kontraktu. Open dostane přesný snapshot/job/operation/schema/content identity descriptor, ověří AAD a vrátí skutečné bytes; `valid=true`, modelový receipt ani JSON string vydávaný za bytes nejsou přijatelnou náhradou. Plaintext žije jen po dobu validace/use, nevstupuje do public returnu, eventu, logu ani auditní evidence a je uvolněn na všech exit cestách podle crypto profilu.
7. Hydratace ověří exact bytes SHA, strict UTF8/JSON včetně duplicate-key rejection, frozen request schema a frozen domain-policy consumer revision. Server musí zachovat skutečné frozen schema/policy bytes a deklarovanou dependency closure. Compiler se instancuje pro konkrétní `(schemaId,bundleDigest,definition)`; dvě archivní verze se stejným `$id` nesmějí být zaměněny ani globálně odmítnuty pouze proto, že jsou různé. V jedné declared closure jsou rozdílné byte digests pod stejnou URI konflikt. Není povolena síťová/current fallback hydratace ani tichá migrace legacy vstupu. Neexistující archive/policy je přesný BLOCKED, nikoli PASS.
8. Consumer ověří actual stored creation receipt a event payload bytes/digests a retained canonical outcome digest; replay marker mění pouze transport a nemění frozen outcome/event. FAILED/UNKNOWN/PENDING po create nesmějí vytvořit nový business create key. UNKNOWN používá původní logical operation pro reconciliation; terminal se odvozuje pouze z přesného retained outcome, ne z EOF nebo aktuálního stavu jobu. Přijetí do DISCUSSING nepředstavuje execution approval ani activation authority.
9. Celé read/hydration uzavření dále vyžaduje native current/approved spec, authority, capability, plan, phase/checkpoint, release/activation a error/cancel producer-consumer vazby. Validní internal root maska nebo callback předávající fixture bytes je neprokazují. Chybové větve před vznikem rootu se čtou přes retained command/outcome, nikoli přes neexistující job root.

Přesné SQL a masky: `generation-create-read-storage.sql`, `generation-root-storage-read.schema.json`, `generation-read-field-mapping.json`; reference use: `generation_read_hydration.py`; per-bundle compiler: `frozen_schema_compiler.py`. Současný reference consumer podporuje current input policy; historical schema-only compilation je doložená, historical domain-policy activation a durable producer zůstávají explicitní povinnosti. Toto omezení nezužuje závazný rozsah §49.4 retention.
