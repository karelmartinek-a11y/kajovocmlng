#### 12.51.2 Locked RETRY source scan and native inherited consumer

Technical specialization of §§12.22,12.41,12.51–12.51.1,25.11,25.16,49.8–49.9 and 51.12. It creates no client authority, terminal-parent requirement, new business role, or implicit execution approval.

`database/generation-retry-scan.sql` defines a bounded server ledger projection adapter. Its source phase has an exact generation_job FK and exact immutable identity/digest; actual operation, attempt, singleton current state and evidence bytes retain their exact producer scope and digests. The scan first locks the selected phase with `FOR UPDATE`, validates expected source job/digest, and reads every operation under that phase FK. The writer gate takes that same phase lock for all insertion, update or deletion attempts. No member insertion, current-attempt change, current-state update or source availability change can occur between scan and its transaction end. The platform producer must hold this transaction through source validation, inventory serialization and child frozen lineage commit; closing the transaction before use is forbidden. An external caller cannot supply a supposedly complete map or a validity flag.

Deferred constraints compare the operation current attempt identity/sequence and current singleton state identity/version/outcome. Evidence belongs to that exact operation/attempt/job/phase and matches the singleton evidence digest. Attempt/evidence rows are append-only; request/target binding/key and producer identity cannot be rewritten. Current state increments its version exactly once. This adapter does not replace the complete §49.8 producer model: dispatch-authority outbox, fences/incarnation/epoch, lifecycle edge guards, contiguous raw-evidence sequence, reconciliation/compensation and terminal checkpoint joins remain mandatory separately. Their absence cannot be presented as whole-ledger closure.

`hydrate_locked_scan` uses the actual phase, operation, attempt, current-state and evidence bytes returned by the SQL scan, verifies their digests and exact masks, constructs the immutable inventory and invokes the declared native outcome classifier. Schema and classifier bytes are pinned immutable dependencies, not model-uploaded executable code. Duplicate, omitted, stale-current, foreign producer, altered bytes and outcome classifier disagreements remain specific failures. Source phase `FAILED`, technical node membership and known source failure are prerequisites for RETRY admission; parent job terminality is not a prerequisite.

Admission and dispatch use separate **server-chosen** stages. `ADMISSION_DISCUSSION` creates no dispatch authority. A known confirmed applied effect remains preserved and is never repeated; a known final failure remains a final failure; `NO_AUTOMATIC_RETRY` remains no automatic retry. These facts do not require inventing a new dispatch policy to discuss the technical failed part. `EXECUTION_DISPATCH` retains the existing final-effect/manual policy blockers and confirmed-effect repeat prohibition. `UNKNOWN`, unresolved/reconciling outcome and unavailable classifier or incomplete locked source scan fail source eligibility; they are not reclassified as known failure. Even a known-not-applied source result only identifies a reusable operation/key relation: actual next-attempt T1, inherited technical commit, current preconditions/fence and pre-dispatch guard are required before execution. Neither stage's content-validation result itself authorizes an external effect.

The native inherited consumer reopens the frozen source revision under its actual retained SchemaAddress and actual bundle bytes. It hydrates every native ArtifactRef/ContractRecordRef, exact schema bundle, typed document/evidence and vector, checks requirement DAG, acceptance/domain/capability coverage, and preserves explicit DesignArtifactExpectation for future generated code. Existing ArtifactRefs require actual bytes; declared future code is neither missing source bytes nor implementation acceptance evidence. RETRY and REPAIR must consume the exact frozen approved revision selected by their own selector. UPDATE must bind the immutable target revision to its actual source specification producer relation; no caller flag substitutes for that relation. A target without such an inherited source can still undergo its allowed discussion admission; it cannot be silently accepted by this inherited-spec consumer.

The child-local inherited specification changes only `/jobId`, gets a new digest and child identity, and retains original source bytes/digest in frozen lineage. It does not create an OWNER approval or inherited execution-authority receipt. Source progress/failure/cancel never changes those frozen inputs. Full generation-rule/verification-obligation declaration closure, source/delegation/Secret-use predicates, precise monitoring repair consumer, protected archived bundle producer and actual execution commit remain mandatory independent contracts.

All fixture evidence here is pre-generation design evidence. PostgreSQL locks and bytes/content tests do not attest the future generated application's runtime behavior. `IMPLEMENTATION_PRODUCTION_ACCEPTANCE` remains `NOT_EVALUATED`.
