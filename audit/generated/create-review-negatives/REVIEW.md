# Independent create boundary review

Input is canonical SSOT SHA-256 `eb4d7e5e5688e898ce4bb89487f86694050f0d3b673bb7333eeab8ef4aa3593c`; see `input.json` for support-file hashes. This review covers two create operations only, no SQL helper, six-state, or UI exposure deep review. It does not certify complete operations or implementation.

## Observed gaps

1. `admit()` treats membership in trusted `valuePolicyTypes` as successful value validation. A CERTIFICATE request containing `not a certificate` is admitted when CERTIFICATE is added to that list. That is a type whitelist, not semantic validation. §72.21 requires valid metadata/value. The admitted PASSWORD witness remains valid under the opaque UTF-8 policy; certificate/key/session/OAuth structured policies need actual independent parsers/predicates or explicit BLOCKED. Do not invent extra password complexity, token prefixes, or browser-state formats merely from type names.
2. Target identity/kind and parent identity are checked, but parent relationship and state/revision evidence are not. Removing all parent state/revision metadata still admits UPDATE. `owner` mismatch metadata is also ignored, but the canonical model is single OWNER: this probe identifies missing contextual evidence and must not silently invent a multi-owner access-control product requirement. §12.3, §12.41, §25.11 and §49.18 require concrete existing target/parent context. Without authoritative applicable-state rules, block that variant, do not borrow a sibling enum.
3. Missing persisted artifact `contentSha256` triggers KeyError, not a structured rejection. This is not a passing negative test. Add a valid FILE witness first, then remove just the digest and require a diagnostic pointing at that source digest. Missing IMAGE mediaType has the analogous `.startswith()` risk; malformed digest types/schema mismatches should be structured BLOCKED.
4. Both existing response schemas accept SUCCEEDED with null output, SUCCEEDED with `terminal=false`, FAILED with null error, and ACCEPTED with `terminal=true`. These are syntactic admissions, not semantic closure. Do not indiscriminately force a create command to terminal if an authoritative accepted/nonterminal branch exists: first define which domain commit each public status promises.
5. Existing generation create event is a generic route lifecycle bag. §12.44 plus `contracts/generation/generation-contracts.schema.json#/$defs/SourceEnum044` explicitly include `generation.job.created`, while §49.5 mandates committed aggregate sequence and same-transaction outbox for consumer events. Domain event, command outcome, and operation terminal event are separate claims. Do not reuse `generation.spec.approved` payload or assert an event is inapplicable merely to reduce a count. No exact `secret.created` public SSE event was identified in the scoped prose; audit/domain outbox obligations still require an explicit treatment.
6. Existing replay reference only tests OWNER/operationId/key/body digest. §49.4 defines a stable locator (operation family, caller authority kind, stable caller object, stable business target key, key digest) distinct from frozen execution tuple (contract revision, caller revision, target, key). Current revisions must not be added to stable lookup. A retry after current registry changes returns the original frozen descriptor/receipt; the server must verify that original descriptor's digest, not regenerate an operation with current revisions. Missing record metadata is currently accepted; this is still an unclosed design claim.
7. Existing UNKNOWN replay correctly avoids new dispatch, but returns only an action. It proves reference admission behavior, not original-operation lookup, retained outcome hydration, immutable event, or read-back closure. A known terminal failure must have stored canonical error/outcome; retryable attempt failure must not be mapped to FAILED_FINAL by an arbitrary `FAILED` flag (§49.4).
8. Raw artifact bytes and digest verification do not prove parser role classification or complete consumer hydration. §12.7 requires raw/canonical digest, provenance/content roles, and forbids upgrading text embedded in a source to OWNER_DECISION. Source parsing and URI fetch postconditions remain obligations after FILE/URL shape checks.

`observed-gaps.json` contains 15 reference/schema probes (including one positive control). Accepted gap probes are deliberately not reported as PASS. `negative-case-specifications.json` supplies 45 mutation specifications and a domain-positive witness recipe; the exact diagnostic names there are proposed reference-validator diagnostics, not newly invented canonical API error codes. Each case has a source pointer and requires an otherwise valid witness. They remain SPECIFIED_NOT_EXECUTED pending authored response/event/commit validators.

The coordinator should rerun relevant probes against the eventual current support/source hashes and integrate approved tests. A source hash match alone does not make the specified cases passing evidence.
