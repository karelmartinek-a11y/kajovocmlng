# OWNER session record administration: list and selected revoke

Scope comprises **owner.session.list** and **owner.session.revoke(id)**. These are a bounded family over the same owner_session records and writer.identity/owner_identity root. This proposal does not resolve current-session/reauthenticate/revokeOthers/revokeAll behavior, and does not repeat the six existing state-field repairs.

`operation-mask-delta.json` replaces six generic request/response/event boundaries with domain masks. It is an author proposal, not effective canonical authority. Coordinator must publish it, its native codecs, registry/schema projections and authoring rules together. Generic refs resolving is not semantic completion.

## Read contract

GET /owner/sessions accepts optional `cursor` and `limit` query parameters, preserving §26.1 cursor pagination and deterministic order. `cursor` is a server-persisted opaque UUID; `limit` is a positive canonical PostgreSQL bigint Counter. Duplicate/unknown query names fail. No request body is accepted; rejecting body bytes is not evidence of a permissible JSON parser. No client can provide owner identity, current-session identity, time, state, authoritative digest or access mode.

Server authenticates either current OWNER session or the single current OWNER API key, retaining §7.1–7.2 OWNER_FULL parity. A web context's current identity comes from its verified session lookup; the API-key channel has no web-session identity and all current flags are false. This is a descriptive projection, not a requirement for API callers to exchange credentials.

The exact public row contains id, createdAt, lastSeenAt, expiresAt, nullable revokedAt/reauthenticatedAt, sessionEpoch, stateVersion, closed deviceMetadata and current. Device metadata proposes exact nullable userAgent plus nullable validated IPv4/IPv6 IP address. This projects the existing §21.4/25.1 device/IP/user-agent requirement without a new tracking identity, lossful normalization or invented size cap. lookup_digest, session_hash and token/CSRF bytes are not public row fields. UTF-8 strings are preserved. Source origins are listed in the delta and source-bound selected passages in authoritative-excerpts.json.

Output also contains observedAt, accessChannel, nextCursor, ownerStateVersion and ownerSessionEpoch. One consistent owner/session snapshot is sorted by canonical UUID. The cursor binds fixed snapshot bytes, owner, route/filter fingerprint, current-session/channel projection, effective page-size/policy revision and next offset. Later changes do not alter frozen rows. Root stateVersion/sessionEpoch values are captured in that same immutable snapshot, rather than mixed with later live values. Changing the bound query rejects; absence/wrong owner rejects. Publication/retention of cursor snapshots and the frozen default page policy need actual shared bindings. Synthetic fixture page size is not a normative default.

No domain event/outbox results from this READ_ONLY operation: catalog record498 explicitly has possibleEffectTrigger NONE, no outbox purposes and CONSISTENT_READ. This precise authority supports NOT_APPLICABLE rather than reducing an inventory count arbitrarily. Security access audit required by §7.2 is distinct from a domain mutation event.

## Selected revoke contract

DELETE /owner/sessions/{id} accepts exact lower-case UUID path identity, no query and no body. If-Match is a required quoted Counter for the selected owner_session.state_version; Idempotency-Key is required and preserved. This is an explicit target-row CAS specialization: owner_identity remains the root lock and its own write uses the version captured under that lock; selecting one session must not increment session_epoch and revoke unrelated sessions. §51.9 requires state_version for standalone lifecycle rows and +1 for every authoritative mutation.

The target must belong to the fixed OWNER, exist, not already be revoked/expired, and have the current OWNER session epoch and expected row version. Preconditions are rechecked in the guarded UPDATE. A zero-row CAS is a typed conflict, not success. OWNER_API_KEY remains available without introducing an extra session requirement. A web mutation consumes valid CSRF and the versioned security reauthentication policy (§30.2); no age threshold is invented. Actual MFA/reauth/CSRF producer and policy publication remain explicitly shared obligations.

The transaction locks root OWNER E10, followed by applicable OWNER session H10 children in explicit UUID order; reads/claimed idempotency and common command authority obey the full §51.6/51.12 hierarchy. It persists command/descriptor, selected session revokedAt and +1 stateVersion, root +1 stateVersion/aggregate_event_sequence, exact event, outbox, audit, terminal result and scoped locator/idempotency outcome atomically. No external dispatch/lease recovery is needed for the selected local mutation. The proposed exact domain event is owner.session.revoked, with sessionId, revokedAt, stateVersion and ownerStateVersion; sequence is the actual root aggregate sequence beginning at1; immutableEventId, aggregateId and occurredAt are required public event fields enabling actual outbox correlation and consumer deduplication. Stable event type is a technical allocation requiring coordinator publication, not a new business capability.

Success response has sessionId, revokedAt, stateVersion, ownerStateVersion and current. A selected current web session can return its already-accepted result and clear the cookie; subsequent authentication using it fails. Other sessions and owner session_epoch remain untouched. Result digest is computed from the effective canonical semantic result profile, not caller claims. Retained exact replay authenticates current credentials first and returns original bytes; a changed request under the same scoped key conflicts. A connection loss during COMMIT yields no guessed domain failure: replay/read of the original command resolves exact persisted success or the actual failure-before-effect result through common §51.12 recovery bindings. Actual unknown-commit/retained outcome locator producer is still required.

## Errors and downstream use

Delta defines closed error branches with precise classification/retry mapping. Request/schema/unknown query, authentication, CSRF/reauth, missing/revoked/expired/epoch-invalid target, stale CAS, conflicting replay, invalid/mismatched cursor and unavailable authoritative dependency have individual predicates. DEPENDENCY_UNAVAILABLE/RETRY_SAME_OPERATION is nonterminal FAILED transport presentation; it does not terminalize the logical business operation. SIDE_EFFECT_OUTCOME_UNKNOWN/RECONCILE_THEN_RETRY uses status UNKNOWN and terminal=false until retained evidence resolves it. Exact error names are technical allocations; generic INTERNAL or UNKNOWN does not satisfy a specific negative witness. Pre-admission transport diagnostics must remain distinct from admitted command outcomes.

UI selected-session action security.revokeSession consumes the row id/stateVersion and existing explicit confirmation (§72.25); it does not create an authority claim. On success it hydrates the actual retained response, updates the selected row, and refreshes the paginated list. Current-session revoke clears local session state. A stale CAS conflict requires refresh and a fresh command. Already revoked, expired or epoch-invalidated selected targets use DO_NOT_RETRY; refreshing the view does not make those rows revocable. Server/private authentication fields cannot be supplied or repaired by the UI.

## Gate distinction and precise remaining obligations

Exact mandatory pre-generation SQL/crypto fixtures remain mandatory where effective normative gates require them; they are not moved wholesale to P02. Actual generated handler, network/header behavior, DB locks, cookie invalidation and UI runtime acceptance belong to implementation acceptance once a real application exists. Full operation closure remains BLOCKED_SHARED_BINDINGS; structural mask improvement is separately reviewable now.
