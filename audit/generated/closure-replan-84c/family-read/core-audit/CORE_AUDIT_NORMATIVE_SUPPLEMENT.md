# Proposed technical supplement: global immutable Audit reads

This supplement is a technical allocation to existing OWNER_QUERY Audit capabilities. It neither grants a new permission nor closes the operation's unavailable producer/fixture obligations. It preserves the strict `urn:kcml:history-query:1` schema (maximum 200) and the separate experience-history maximum-500 schema.

## Exact scope and HTTP/native mapping

Only `route.0451 / audit.event.list / GET /audit/events` and `route.0452 / audit.event.read / GET /audit/events/{id}` are changed. Component/job-scoped Audit routes and generation/agent history routes are excluded. Existing authentication, guard, correlation, invocation and response envelopes remain authoritative. Both GET routes reject nonempty bodies; the read-by-ID route rejects every query parameter. The UUID path is canonical lowercase with hyphens. HTTP percent escapes and decoded UTF-8 must be valid.

The list route binds the existing CORE200 history query, not the experience-500 UI query. Its native query contains all thirteen fields required by the existing schema. Missing nullable HTTP scalar fields map to native null; nonnullable fields must be present. A provided empty string remains an empty string and is checked by its actual schema; the literal string `null` is never guessed as null. `recordKinds` is repeated, nonempty and unique. Other fields occur at most once. `limit` is canonical positive decimal, converted to a native integer in 1–200. No scalar gets a guessed default. The interval is `[from,to)` and `from < to`; the source schema's date-time format applies. Unknown parameters, malformed encodings, duplicates, wrong kinds/types/enums and missing required parameters are specific validation failures before a read is admitted.

An experience-500 Dashboard/chat query is a distinct consumer contract. It requires an explicit adapter with an authoritative mapping for every requested filter and ordering. Such an adapter cannot silently drop a filter, reclassify a channel, equate generation-job and run identity, or expand a CORE200 page. This candidate supplies no such adapter.

## Physical projection and byte hydration

`AuditRecord` has two explicit stored-stream variants. `DOMAIN_EVENT_AUDIT` projects an actual immutable audit row with its domain-event FK. `GENERATION_PREROOT_OUTCOME_AUDIT` projects the effective §12.54 typed retained command outcome when `domain_event_id` is NULL. Both bind the actual logical command and its authoritative OWNER identity. The SQL starts from every audit row and LEFT JOINs the two typed stream roots; it never silently excludes NULL-domain-event audits. Unknown or broken stream links produce an explicit integrity failure, not an omitted result. Exact column mappings are in `field-source-map.json`. There is no `values`, `slot`, `canonicalJson`, arbitrary domain object, editable identity, or client-created authority.

`canonicalAuditBytesBase64`, domain-event `eventPayloadBytesBase64`, and pre-root `retainedOutcomeBytesBase64` are explicit encodings of existing native BYTEA columns. The pre-root variant reports no fabricated aggregate, created-domain-event payload or delivery outbox. Its prospectiveJobId is explicitly the command target, not proof that a root existed at that retained stage. Their consumer capability is immutable byte inspection, not execution or interpretation of an arbitrary business event. This is a real byte boundary: base64 validation, original-byte hydration, payload digest and the canonical framed Audit-chain hash must pass before the inspector exposes bytes. Event-schema identity/digest are reported from the stored domain-event row. Applying a business event requires that event's actual schema/archive authority and a capable consumer; this inspector does not supply it.

The SQL inspector does not cast audit bytes to JSON or regenerate them. PostgreSQL base64 presentation line breaks are removed only from the encoding, preserving every original byte. The separate named current Secret command producer's 13-field audit JSON profile is verified against its actual canonical constructor and physical identities. That profile is not imposed on every historical or other producer's Audit row. Unknown Audit JSON producer profiles remain valid native byte-inspection inputs if the actual framed hash is correct; they cannot acquire a guessed parsed-domain interpretation.

The effective pre-root variant preserves the exact eleven-field immutable retained wire outcome defined by `generation-create-preroot.sql`. It does not rewrite older outcome bytes into today's thirteen-field public response. Status/terminal/error are read from the retained bytes, not the mutable current command state; a historical ACCEPTED audit remains ACCEPTED after that command later succeeds. The outcome digest and source SQL's objectId=logical command, actorId=OWNER, and afterDigest=retained outcome digest assertions are checked before inspection. Retained stateVersion comes from the immutable outcome row's key. Error tuple classification/retry pairing is derived from the exact canonical retained-error table. Known failure, cancellation, retryable persistence failure and unknown reconciliation outcomes retain their own terminal meanings.

## List-filter producers, snapshot and completeness

The source CORE query includes fields not physically present in `audit_event`: run/component/client, channel, direction, result, duration. An immutable `OriginProjection` therefore must be published by the actual authenticated domain ingress/execution producer, bound to `auditId`, `eventHash` and exact `sourceContextDigest`. It must copy identities/classification from that source, not infer them from aggregate names, command UUIDs, severity, display labels or a caller's `valid` flag. `recordedAt` is the source DB recording timestamp and may not be substituted with the domain occurrence timestamp.

This is a required technical producer interface, not a verified existing publisher. The reference inspector does not manufacture origin projections. It also does not manufacture snapshot watermarks, cursors, continuous coverage, provenance or the mandatory access-audit append. `CoreResult` closes their value masks while these actual producer obligations remain OPEN. `COMPLETE`, `PARTIAL`, and `UNAVAILABLE` preserve the source completeness rules. Cursor identity binds normalized filters, authorization, ordering and snapshot; invalid/expired cursors require the existing `HISTORY_CURSOR_INVALID` restart flow.

The operation uses existing `CONSISTENT_READ` (`REPEATABLE READ READ ONLY`) and cannot turn a read snapshot into a subsequent domain mutation without a new authoritative transaction/CAS. Snapshot access and any mandatory access-audit append need their own explicit transaction ordering; the candidate does not silently write into a READ ONLY transaction or omit the access audit.

## Events and errors

READ_ONLY and `outboxPurposes=[]` do not cancel the existing required `OPERATION_ADMITTED`, `OPERATION_STATE_CHANGED`, and `OPERATION_TERMINAL` audit-event types in the native operation records. The operation-event masks and applicability are deliberately unchanged. Mapping them to exact producers, payloads and retained outcomes is `AUDIT.CORE.OPERATION_EVENTS`, still OPEN. No NOT_APPLICABLE claim is made.

The candidate parser/inspector's exact diagnostic predicates are in `error-predicates.json`, with positive-derived proofs. Existing authentication/lifecycle/cancellation/unknown envelopes and their admitted/terminal retention remain unchanged. These internal diagnostics are not a silent replacement of every public operation error. The public stable-error mapping and mandatory event/access-audit transaction producer remain an explicit definition/fixture dependency.

## Gates

Request/response masks plus byte inspection are the bounded integration proposed here. Whole-operation semantic closure remains false. Required pre-generation producers and fixtures are listed in `remaining-obligations.json`; future generated backend runtime acceptance is separately NOT_EVALUATED. The PostgreSQL 18.6 proof executes the exact canonical hash function bytes. A separate strictly read-only proof consumes the existing exact canonical pre-root-to-success fixture: both persisted Audit rows are projected (2/2), including the historic pending row after success. It does not claim a complete authenticated read/audit publication transaction or a production application.
